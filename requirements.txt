# Direct dependencies pinned with compatible-release (~=) so reproducibility
# matches the version we tested against while still allowing patch-level
# updates (e.g. 8.1.7 → 8.1.* but not 8.2).
#
# This file is the editable SOURCE of truth. The CI installs from the
# checked-in `requirements.lock`, which is a hash-locked, fully-resolved
# transitive closure of these pins. The lock is what makes installs
# reproducible and tamper-resistant.
#
# After editing this file, regenerate the lockfile:
#
#     python -m pip install pip-tools
#     pip-compile --allow-unsafe --generate-hashes \
#         --output-file=requirements.lock requirements.txt
#
# Then commit BOTH files together. CI installs with
# `pip install --require-hashes -r requirements.lock`; a stale lock will
# fail with HashMismatch, preventing accidental drift.
# Reference: https://pip.pypa.io/en/stable/topics/repeatable-installs/
